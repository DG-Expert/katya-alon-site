# מדריך: עריכת סדנה דרך Google Sheets (מדריך למשתמשת)

> **סטטוס: תכנון בלבד.** הלשונית `ניהול סדנאות` קיימת בגיליון, אבל **התפריט `סדנאות` והכפתורים עדיין לא קיימים ולא נבדקו**. כל מה שמופיע כאן תחת "שלב 2" ואילך מתאר את מה שייבנה לפי `docs/WORKSHOP_SHEETS_AGENT_SPEC.md`. אל תנסו ללחוץ על משהו שאינו קיים, ואל תניחו שהוא עובד לפני שמסומן כאן "נבדק".

## 1. מה זה, ומה זה לא

**מה זה:** מקום נוח (לשונית בגיליון `Katya Alon - Workshop Registrations`) לעריכת טקסטים ופרטים של סדנה *עתידית*, בלי לגעת בקבצי האתר.

**מה זה לא:**
- לא "לחצתי ופורסם". כל שינוי עובר **בקשת שינוי (Pull Request) בגיטהאב** שמישהו בודק ומאשר. רק אחרי אישור האתר מתעדכן.
- לא עורך את הלשונית `Registrations`. היא לא נקראת ולא נכתבת על ידי המנגנון.
- לא משנה סודות, מפתחות או הגדרות Cloudflare.
- לא מבטיח שהכול אוטומטי. יש שדות שמצריכים עבודה ידנית (ראו סעיף 5).

## 2. מה בלשונית `ניהול סדנאות`

- שורות 1-3: כותרת ואזהרות. אל תמחקו.
- שורה 4: כותרות העמודות. **אל תשנו, תוסיפו או תזיזו עמודות.**
- עמודות A:J: תחום · מפתח YAML · תווית · ערך (עברית או ערך יחיד) · English · Русский · סוג · חובה · מצב · עזרה.
- שורות 5-56: שלד ראשוני. שדות טכניים (מזהה סדנה, תאריכים, שעות) מולאו. טקסטים בעברית/אנגלית/רוסית **ריקים ומסומנים `יש לייבא`**.
- **אל תכתבו את הטקסטים מההתחלה ביד.** קודם מייבאים מהאתר האמיתי (שלב 3), כדי שלא יאבדו נוסחים קיימים.
- עמודה B (מפתח YAML) ועמודה G (סוג) הן "נעולות": משנים רק את D/E/F.

## 3. שלבי הפעלה (חד-פעמיים; מבוצעים רק אחרי שהסוכן סיים והכול נבדק)

עשו כל שלב בנפרד, ואל תמשיכו אם משהו נראה לא כמצופה.

### שלב 0 – לא נוגעים בהרשמה החיה
פריסת הקוד החדש של האירוע הדינמי (Worker + Apps Script) **טרם נעשתה**. הדבקה שנשמרה ב-GAS אך לא נפרסה אינה משפיעה על הרשמות עד שתפרסמו גרסה חדשה.
```
node --test test/*.test.mjs
node scripts/sync-event.mjs --check
```
- רק כשהשניים עוברים, ובדיקת הרשמה אחת מתוכננת על ידיכן, מחליטים על פריסה. **המדריך הזה לא מפרסם כלום.**

### שלב 1 – גיבוי
```
git status
git log -1 --oneline
```
- רשמו את מזהה הקומיט. זו נקודת החזרה (ראו סעיף 8).
- בגיליון: קובץ ← יצירת עותק, ושם `גיבוי לפני סדנאות`.

### שלב 2 – התקנת `Publish.gs` (נבנה על ידי הסוכן, לא קיים עדיין)
1. בגיליון: הרחבות ← Apps Script (סקריפט **הצמוד לגיליון**, לא ה-Web App של ההרשמות).
2. הוסיפו קובץ בשם `Publish.gs` עם תוכן שהסוכן מסר (לא ממציאים אותו ידנית).
3. רעננו את הגיליון: אמורה להופיע תפריט `סדנאות`. אם לא מופיע, **עצרו** ופנו לסוכן.

### שלב 3 – ייבוא מה-YAML האמיתי
- `סדנאות ← ייבוא מהאתר`. התוצאה: כל השורות מתמלאות מ-`content/workshop.yaml`, והמצב משתנה מ`יש לייבא` ל`מיובא`.
- ודאו בעיניים: 3 שפות מלאות, אין תאים ריקים בשדות חובה.
- **לשונית שלא יובאה לא ניתנת לפרסום** (הכפתור יסרב).

### שלב 4 – חיבור GitHub (פעם אחת, על ידי בעלת המאגר)
- יוצרים טוקן **מוגבל** (Fine-grained PAT): רק למאגר הזה, הרשאת `Actions: write` ו-`Contents: read` בלבד.
- שומרים אותו **רק** ב-Apps Script ← הגדרות פרויקט ← Script Properties (שם: `GH_DISPATCH_TOKEN`).
- **לעולם לא בתא בגיליון, לא בצ'אט ולא בקובץ.** מי שיכולה לערוך את הסקריפט רואה אותו, לכן רק אנשים מהימנים עורכים את הגיליון.
- הערך עצמו אינו מופיע במסמך הזה ואיני מנחש אותו.

## 4. זרימת עבודה רגילה לסדנה עתידית (אחרי שהכול הופעל ונבדק)

1. ערכו תאים בעמודות D/E/F בלבד.
2. `סדנאות ← בדיקה (Validate)`: מציג שגיאות/אזהרות בעמודה I. תקנו עד שירוק.
3. `סדנאות ← שליחה לבדיקה (Submit PR)`: נוצרת בקשת שינוי. אין פרסום.
4. `סדנאות ← בדיקת מצב`: מציג קישור ל-PR ותוצאת הבדיקות האוטומטיות.
5. בגיטהאב: קראו את ה-diff, ודאו שרק מה שרציתן השתנה, ואשרו/מזגו.
6. אחרי המיזוג: האתר מתעדכן; ה-Worker וה-GAS מתעדכנים לפי הסעיף "שלבי עדכון" בספק. **רק אחרי שמופיע `פורסם`** מותר להפיץ קישורים.

## 5. מה אוטומטי, מה חצי-ידני, מה ידני

| נושא | רמה | הערה |
|---|---|---|
| טקסטים בכותרות, פסקאות, כפתורים (HE/EN/RU) | אוטומטי דרך PR | חייבים 3 שפות |
| מחיר, מחיר מקורי, מחיר למפגש | אוטומטי + בדיקות | בדיקת עקביות: מחיר למפגש × מפגשים = סה"כ |
| תאריך מפגש ראשון/שני, שעות, מספר מפגשים | אוטומטי (`event:`) | מסונכרן ל-Worker ול-GAS |
| **תאריך מועד אחרון להנחה בתוך משפטים** (למשל "עד 10.11.2026") | **חצי-ידני** | הטקסט חופשי; המנגנון רק מזהה אי-התאמה מול שדה תאריך ומתריע |
| **מילים במקום מספרים** ("שני מפגשים", "ארבע שעות") | **ידני** | צריך לעדכן בכל שפה כשהמספר משתנה; יש אזהרה |
| **גרסת הסכמה (consent version)** | **ידני + אישור משפטי** | שינוי ניסוח הסכמה = גרסה חדשה בכל המקומות (Worker + אתר); לא נערך בלשונית |
| קישור יומן / אימייל אישור: נושא וגוף | **ידני בשלב ראשון** | הפיצ'ר הדינמי מטפל כיום רק בתאריך/מפגשים/שעות. נושא המייל קבוע לעורכי דין |
| מזהה סדנה (`workshop_id`) | מוגן | משתנה לגרסה חדשה; ראו סעיף 6 |
| סדר/הצגת חלקים (`sections`, `layout`) | מוגבל לרשימה מותרת | |
| נתיבי תמונות | מוגבל | רק תחת `assets/images/` וקבצים קיימים |
| סודות, כתובות, Turnstile, מקורות מותרים | **אסור מהגיליון** | |

אל תבטיחו לעצמכן "שינוי תאריך והכול מתעדכן". תאריך מתעדכן באתר ובמייל; **מועד ההנחה בטקסט, קישור היומן ונושא המייל לא בהכרח**.

## 6. מזהה סדנה, ושמירה על הרשמות קיימות

- בסדנה חדשה מחליפים `workshop_id` (למשל `lawyers-social-2027-03`). זה פותח "מרחב" חדש לבדיקת כפילויות, כך שנרשמים קודמים לא חוסמים חדשים.
- הרשמות ישנות נשארות ב-`Registrations` ללא שינוי.
- **חשוב:** בעת המעבר, דפדפן שפתח את הדף הישן עלול לשלוח מזהה ישן. הספק דורש שה-Worker יקבל זמנית גם את המזהה הנוכחי וגם הקודם, כדי לא לשבור הרשמה בזמן הפריסה.

## 7. ביטחון – כללי ברזל

- לא שמים סיסמאות/טוקנים/HMAC/Cloudflare בגיליון.
- המנגנון לא קורא ולא שולח נתוני `Registrations` לשום מקום.
- מי שעורכת את הגיליון יכולה לשנות את הטקסט שייכנס ל-PR; **המאשרת בגיטהאב היא הגנת הקצה**. אל תמזגו בלי לקרוא.
- אם נחשף טוקן: מחקו אותו בגיטהאב מיד, צרו חדש, עדכנו Script Properties.

## 8. חזרה לאחור (Rollback)

| מצב | פעולה |
|---|---|
| שינוי בטעות בגיליון, לא נשלח | `סדנאות ← שחזור מהאתר` (מייבא שוב מה-YAML הנוכחי) או `עריכה ← היסטוריית גרסאות` |
| PR שגוי, לא מוזג | סגרו את ה-PR בגיטהאב. לא קרה כלום לאתר |
| מוזג ופורסם, יש בעיה | בגיטהאב: **Revert** על ה-PR (מייצר PR חדש). אחרי מיזוג, האתר חוזר |
| ה-Worker נפרס עם מזהה שגוי, הרשמות נכשלות | פרסום מחדש של הקומיט הקודם (מזהה הקומיט משלב 1) – `git revert` ואז סנכרון |
| GAS שגוי | Apps Script ← פריסות ← חזרה לגרסה קודמת |

## 9. מתי המשימה נחשבת גמורה (Definition of Done)

סמנו רק אחרי בדיקה בפועל:
- [ ] `Registrations` לא שונתה (השוואת מספר שורות לפני/אחרי).
- [ ] ייבוא מילא 3 שפות לכל השורות; אין `יש לייבא`.
- [ ] שדה לא חוקי נחסם בבדיקה (ניסו מחיר שלילי, תאריך שני לפני ראשון, שפה חסרה).
- [ ] Submit יוצר PR; ה-PR מכיל **רק** נתיבים מותרים.
- [ ] כל הבדיקות האוטומטיות עוברות (`node --test test/*.test.mjs`).
- [ ] אחרי מיזוג האתר מציג את הטקסט החדש בעברית, אנגלית, רוסית.
- [ ] הרשמת ניסיון **מבוקרת, שאושרה מראש על ידיכן**, מצליחה, והמייל מציג תאריך נכון.
- [ ] Rollback נוסה פעם אחת על PR מבחן.
