# פרסום תוכן סדנה מ-Google Sheets לענף טיוטה

`gas/Publish.gs` הוא קובץ נפרד לקוד Apps Script הצמוד לגיליון. הוא מוסיף את התפריט `סדנאות` עם `בדיקת נתונים` ו-`דחיפת שינויים ל-GitHub`. הוא אינו נוגע ב-`Registrations`, ב-`Code.gs`, בפריסת ה-Web App או ב-Worker.

הדחיפה עושה GET של `content/workshop.yaml` מענף הטיוטה הקבוע `sheet-workshop-drafts`, מחליפה רק את 143 הנתיבים שבסכמת גיליון הניהול, ושולחת PUT יחיד עם ה-SHA שהתקבל. לכן GitHub דוחה עדכון מתחרה/stale. אין אפשרות לבחור ענף, ו-`main` אינו יעד אפשרי.

## התקנה והגדרה

1. פותחים את Apps Script של הגיליון הצמוד, מוסיפים קובץ `Publish.gs`, ומדביקים את [הקובץ](../gas/Publish.gs). אין לשנות את `Code.gs`.
2. שומרים ומרעננים את הגיליון. התפריט החדש יופיע רק לאחר פתיחה/רענון.
3. יוצרים ב-GitHub מראש את הענף `sheet-workshop-drafts` מתוך הקוד המקומי שסונכרן ונבדק. אין לשנות בקוד או ב-Script Properties את יעד הענף. אם חסרים בענף שדות `event` העדכניים, הדחיפה נעצרת עם הודעת סנכרון; מסנכרנים את baseline של ענף הטיוטה ובודקים אותו לפני ניסיון חדש.
4. יוצרים Fine-grained PAT עבור `DG-Expert/katya-alon-site` בלבד, עם **Contents: Read and write** בלבד, ושומרים אותו ב-Script Properties בשם `GH_WORKSHOP_PAT`. לא כותבים אותו בתא, בקוד או ביומן.
5. רק אחרי שסונכרנו ונבדקו השינויים המקומיים, מגדירים גם `WORKSHOP_PUBLISH_ARMED` לערך המדויק `I_HAVE_SYNCED_LOCAL_CHANGES_AND_REVIEWED_DRAFTS`. בלי ערך זה, הכפתור נחסם לפני כל קריאת GitHub.
6. אין להגדיר `GH_WORKSHOP_BRANCH`: הנכס אינו בשימוש והיעד נעול ל-`sheet-workshop-drafts`.

נדרשת הרשאת Apps Script `script.external_request` בנוסף להרשאות הקיימות של פרויקט ההרשמות. לאחר ההדבקה מאשרים את ההרשאה; אין צורך בפריסה מחדש של Web App כדי שהתפריט יעבוד.

## גבולות בטיחות

- הדחיפה מסרבת אם נותרה שורה במצב `יש לייבא`, אם שדה חובה/תרגום חסר, אם סוג מספר/תאריך אינו תקין, או אם נתיב אינו מורשה.
- `registration.*` ו-`system.*` אינם נתיבי גיליון ואינם נכתבים לעולם. שורות `form.privacy_note`, `form.privacy_notice` ו-`form.consent` הן תצוגת קריאה בלבד: ערכיהן אינם חוסמים את הדחיפה ואינם נכתבים, כדי לשמור על הטקסט המשפטי.
- הסכמה תומכת בכל 143 השורות המיוצאות, כולל מערכים קבועי-אורך ומפות תרגום HE/EN/RU. כל נתיב אחר, נתיב כפול, סוג שגוי, תאריך לא תקין, נכס לא מורשה או ערך רב-שורה נחסמים.
- תא `event.second_session_date` ריק (שדה לא-חובה) נכתב כ-`null`; `boolean` ו-`number` נכתבים כסוגי YAML ולא כמחרוזות.
- אחרי הדחיפה נוצרת התחייבות בענף טיוטה בלבד. יש לפתוח PR, לקרוא את ה-diff, ורק אז למזג לפי תהליך נפרד. אין CI/CD ואין פריסה אוטומטית כאן.

## לפני כל דחיפה

1. מריצים `סדנאות ← בדיקת נתונים` ומתקנים כל תא בעמודת מצב שאינו `תקין`.
2. ודאו שהענף המקומי/טיוטה סונכרן וששינויי האירוע הדינמיים הלא-מחויבים נבדקו לפני דריכת ה-arm.
3. דוחפים, פותחים PR ומוודאים שה-diff מכיל רק `content/workshop.yaml` וששדות ההרשמה המוגנים לא השתנו.

חזרה לאחור: אם הקומיט לא מוזג, מוחקים/מתקנים אותו בענף הטיוטה. אם מוזג, יוצרים PR של revert. אם נחשף טוקן, מבטלים אותו ב-GitHub ומוחקים את `GH_WORKSHOP_PAT` מיד.
